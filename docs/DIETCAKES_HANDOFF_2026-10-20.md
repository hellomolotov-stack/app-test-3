## 1. Что сейчас работает (продакшен)

### Скидка по карте интеллигента
Правило: календарный месяц по Москве, первые 15 000 ₽ покупок до скидки – 10%, сверх – 5%. Лимит общий для магазина (офлайн) и сайта (онлайн).

- **Сервер:** `api/dc-loyalty.js` + `lib/dietcakes-loyalty/` (журнал, подпись карт). Журнал Firebase `dietcakesLoyalty/cards/<uid>` (рабочий; тестовый `dietcakesLoyaltyPilot` больше не используется).
- **Офлайн-касса в боте @yaltahiking_bot:** `integrations/telegram-bot/dc_cashier.py` (на сервере `/opt/hiking_bot/dc_cashier.py`). Кассир: `/cashier` → сканирует QR → вводит сумму → «Покупка оплачена — учесть».
- **QR в приложении:** у владельцев активной карты на главной кнопка «показать QR» (вместо «поддержка», так решил пользователь) → поп-ап 🪪 «покажи карту на кассе» → «жить здорово» → личный подписанный QR. Код: `js/ui/card-qr.js`, библиотека QR `assets/vendor/qrcode-generator.js`.
- **Онлайн:** приложение кладёт в ссылку на магазин подписанный ID карты (`#card=dc1_<uid>_<sig>`), страница бокса передаёт его в корзину, плагин магазина спрашивает у сервера скидку и ставит строку «Скидка по карте интеллигента». При оплате заказа покупка пишется в журнал (reserve+confirm, ссылка `wc<номер>`), при отмене/возврате лимит восстанавливается. Общий купон `intelligent` из приложения больше не подставляется (но в WooCommerce он ещё действует при ручном вводе – отключить после первых живых онлайн-заказов).

### Плагин магазина «Хайкинг бокс – клуб «Интеллигенция»» (версия 0.3.3, установлен)
Исходник теперь в репозитории: `integrations/dietcakes-checkout/hi-club-checkout/` (основа – пилот 0.2.0 от Codex). Тесты: `node tests/run.mjs` (49) и `node tests/run-loyalty.mjs` (31) в `integrations/dietcakes-checkout/`, рантайм PHP-wasm в `/private/tmp/hi-checkout-runtime` (если пропал – `npm i @php-wasm/node @php-wasm/universal` туда). Архив для установки – `hi-club-checkout-0.3.3.zip` там же. Устанавливается: Плагины → Добавить → Загрузить → «Заменить текущую версию загруженной».
- Настройки: WooCommerce → «Хайкинг бокс клуба»: режим «Включён», скидка «Включена», ключ магазина задан (значение – только в Vercel `DC_STORE_KEY` и в настройке плагина).
- Делает: способ «Получить на хайке» для переходов из приложения (без 3% за самовывоз, только СБП, дата и маршрут в заказе); скидка по карте; сроки заказа; уведомления о заказах на хайк в бот; сохраняет подписанный Telegram ID покупателя.
- Обычные покупатели магазина ничего из этого не видят.

### Сроки заказа «на хайк» (ограничения магазина: доставка 10–20, последний выезд 19:30, готовая еда готовится 2 дня)
- без готовой еды – до 17:00 накануне хайка;
- с готовой едой (категория «Готовая еда» и подкатегории) – до 20:00 за два дня.
Проверяет плагин (нельзя оформить) и подсказывает страница бокса.

### Уведомления о заказах боксов (бот)
- Оплачен/отменён заказ «на хайк» → сообщение организатору (Telegram ID 163665735) и всем сотрудникам магазина: номер, хайк, имя, телефон, состав, сумма, скидка, итог по хайку.
- Накануне хайка в 17:05 МСК – сводка на завтра (Vercel Cron `5 14 * * *` → GET `/api/dc-loyalty` с `CRON_SECRET`).
- Правило: от 2 000 ₽ на хайк магазин везёт боксы организатору домой, меньше – организатор забирает сам.
- Заказы хранятся в Firebase `dcHikeOrders/<дата>/<номер>`. Там есть тестовая запись `2000-01-01/TEST1` – можно удалить.

### Сотрудники магазина в боте
`/shop` (только владелец, `DC_OWNER_IDS`, по умолчанию 163665735) → список сотрудников с кнопкой «убрать» + одноразовая ссылка-приглашение на 7 дней. Сотрудник по ссылке получает кассу (`/cashier`) и уведомления о заказах, но не права администратора бота. Хранение: Firebase `dcShopStaff/members`, `dcShopStaff/invites`. Кассиров магазина пока не добавляли.

### Отмена участия в хайке при оплаченном боксе
`removeParticipant` в `js/firebase.js` → API `hike_cancelled` → бот пишет покупателю: «отменить заказ и вернуть деньги» (только до крайнего срока) / «заберу сам в магазине». Выбор уходит организатору и сотрудникам магазина. Возврат денег делает магазин в WooCommerce (или в кабинете ЮKassa – не проверено, умеет ли их плагин СБП возврат из заказа). После отмены заказа магазином покупатель получает сообщение.
