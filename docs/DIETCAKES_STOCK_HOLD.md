# Задача: товары бокса «пропадают из наличия» у других покупателей

Дата постановки: 21.10.2026. Статус: 0.4.2 установлена на Dietcakes; WordPress подтвердил обновление, настройки дополнения открылись без ошибки. Реальные оплата и отмена по очереди в магазине не тестировались. Выбран вариант 3 с явно принятым пользователем риском одновременной покупки последней единицы. Сначала прочитать `docs/DIETCAKES_ACCESS_RUNBOOK.md` и `docs/DIETCAKES_HANDOFF_2026-10-20.md`; dietcakes.ru открывать ТОЛЬКО в Google Chrome, по регламенту.

## Симптом
Пользователь из приложения нажимает в конструкторе «Оформить», товары попадают в корзину и на оформление. С другого устройства часть этих товаров уже «нет в наличии».

## Что известно
- Сама корзина WooCommerce товары не резервирует. Наш конструктор (`assets/dc/hiking-box.js`, копия в плагине) и плагин `integrations/dietcakes-checkout/hi-club-checkout/` остаток при добавлении в корзину не уменьшают (проверено по коду 21.10).
- Наиболее вероятная причина – штатный механизм WooCommerce:
  1. **«Удерживать запасы (минуты)»** (WooCommerce → Настройки → Товары → Запасы, по умолчанию 60): при нажатии «Оформить заказ» создаётся заказ «Ожидает оплаты», товары сразу вычитаются из остатка и держатся до оплаты (СБП) или до отмены по таймеру.
  2. Либо резерв под черновик заказа (~10 мин) при открытии страницы оформления (блочное оформление).
- Если товара на складе 1–2 шт., одна неоплаченная попытка (в т.ч. наши тесты) скрывает его для всех.

## Сначала проверить (только чтение, по регламенту, в Chrome)
1. WooCommerce → Заказы: есть ли заказы «Ожидает оплаты» от тестов (их можно отменить вручную).
2. Настройки → Товары → Запасы: значение «Удерживать запасы».

## Варианты
1. Уменьшить «Удерживать запасы» до 10–15 мин – одна настройка, но на весь магазин (решает Михаил).
2. Плагином не держать запасы для неоплаченных заказов бокса (`_hi_club_source = intelligentsia`): списывать только после оплаты. Минус – возможна продажа последней штуки двоим.
3. **Выбрано: вариант 2 + защита от перепродажи:**
   - для заказов бокса (клубный контекст плагина) не удерживать/не списывать запасы до оплаты;
   - перед оплатой (валидация оформления) плагин проверяет реальный остаток каждой позиции; если не хватает – ошибка «товар только что закончился, замени его», до оплаты не пускать;
   - неоплаченные заказы бокса автоматически отменять через 15 минут (а не 60);
   - обычные заказы магазина и общие настройки не трогать.
4. Временная мера: тестовые неоплаченные заказы сразу отменять.

## Где реализовывать
- Плагин: `integrations/dietcakes-checkout/hi-club-checkout/hi-club-checkout.php` (тесты `node tests/run.mjs`, `run-loyalty.mjs`, `run-box.mjs`; рантайм php-wasm в `/private/tmp/hi-checkout-runtime`).
- Полезные хуки WooCommerce (сверить с версией 10.5 на сайте): `woocommerce_can_reduce_order_stock`, `woocommerce_payment_complete_reduce_order_stock`, `woocommerce_hold_stock_minutes`, `woocommerce_cancel_unpaid_orders`, резерв черновиков – `ReserveStock` / фильтр `woocommerce_order_hold_stock_minutes` (проверить наличие).
- Выпуск: поднять версию, `sync-frontend.sh` (если менялся конструктор), zip, обновить плагин в админке через Chrome по регламенту. Скидка по карте и посредник API (`api.intelligentsia-club.ru:8444`) уже работают – не сломать.

## Реализация 0.4.2 (21.10.2026)
- Отдельный модуль `hi-club-checkout/stock-policy.php`. Только новые заказы classic checkout с `_hi_club_source=intelligentsia` и `_hi_club_stock_policy=after-payment-v1`; старые заказы без этой метки автоматически не мигрируются (повторная отправка оформления заново применяет текущую политику).
- Штатный `woocommerce_order_hold_stock_minutes` возвращает0 только для них. До paid/date_paid блокируются обе точки списания, включая раннюю проверку `woocommerce_payment_complete_reduce_order_stock`, чтобы pending/on-hold не получили ложный stock_reduced. После оплаты работает штатное однократное списание Woo.
- Проверка остатков перед созданием заказа и при повторной оплате: агрегирование по stock-managed товару, учёт чужих нативных резервов. Это не атомарная защита от перепродажи; риск принят пользователем.
- Одна задача Action Scheduler на900с после создания. Отменяются только помеченные pending/on-hold без факта оплаты; обычные/старые/оплаченные заказы не затрагиваются. Очередь может сработать позже15мин, если нет фоновых запусков. Просроченная повторная оплата через магазин блокируется независимо от очереди; выданную внешнюю ссылку СБП дополнение у провайдера не отзывает.
