# Тексты интерфейса

Все подписи, кнопки, статусы, теги и заголовки интерфейса пишем со строчной буквы. Имена людей, названия мест, брендов и аббревиатуры сохраняют свой регистр: «новое письмо Макса», «хайк на Демерджи». Не применяем сплошной lowercase через CSS или к пользовательским текстам: он испортит имена и названия.

# Передача работы между ИИ
Источник состояния каждой правки — GitHub PR и его история. В описании PR фиксируй задачу, реализацию, результаты проверок, что осталось, имя ветки и SHA; добавляй ссылки на Preview и Production, если они есть. В новой сессии сначала читай этот файл, PR и актуальное состояние `main`. Пока PR открыт, продолжай ту же ветку. Не помещай в публичный репозиторий закрытый контекст или секреты.

# Сторис о новых владельцах карт

Публикуй сторис о новой карте только после присвоения участнику его персонального изображения карты. Оплата и активный статус сами по себе не считаются выдачей изображения. Если изображение ещё не присвоено, сторис должна оставаться вне ленты. После присвоения используй именно изображение из записи участника. Если сторис уже создана, обнови её изображение в существующей записи, сохранив текст и просмотры.

# Штатный выпуск Mini App

Макс разрешил постоянный выпуск реализованных правок Mini App в рамках поставленной задачи. Штатное назначение для кода — GitHub `hellomolotov-stack/app-test-3`. Production — привязанный Vercel-проект `mvmolotov-1307s-projects/app-test-3` и домен `app-test-3-delta.vercel.app`. Это разрешение включает отправку рабочей ветки, создание PR в защищённую `main`, слияние после обязательных проверок и штатную публикацию Vercel. Для каждой такой правки отдельное «публикуй» не требуется.

1. Проверь репозиторий и актуальную `main`. Сделай чистую ветку от неё и проверь, что в diff только изменения текущей задачи и материалы, допустимые для публичного GitHub.
2. Выполни соразмерные проверки, отправь ветку и открой PR. Если обязательные проверки ещё идут, включи GitHub auto-merge для готового PR. Если PR уже готов к слиянию, слей его обычным способом после проверки текущего SHA. Защита `main`, `Mini App release checks` и Vercel остаются частью выпуска.
3. Дождись слияния и успешного Production на Vercel для коммита слияния. Сохраняй согласованную аудиторию пилотов. Сообщи, что именно вышло и что удалось проверить.

Запросы на анализ, варианты дизайна и макеты сами по себе завершаются соответствующим материалом. Явное «только локально», «только Preview» или «пока не публикуй» ограничивает выпуск для этой задачи. Постоянное разрешение относится к названному репозиторию и его Vercel-проекту. Секреты, закрытый контекст и пользовательские данные остаются вне публичного GitHub. Правила проекта фиксируют разрешение Макса. Управляемая автопроверка Codex применяет свою политику и может остановить конкретную операцию.
